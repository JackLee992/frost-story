# 《冰霜物语》游戏设计书目与前三章二次迭代

> 调研与落地日期：2026-09-13
> 本文不是书摘，也不复制任何书中的案例、关卡或文字。它核对书目与公开目录，提炼可验证的设计问题，再记录本项目实际采用或暂缓的改动。

## 1. 先核对书名

用户提到的“游戏设计的 23 个技巧”应为大野功二的《游戏设计的 **236 个技巧：游戏机制、关卡设计和镜头窍门**》（人民邮电出版社，ISBN 9787115406088）。[图书目录与出版信息](https://www.tenlong.com.tw/products/9787115406088)

该书的主体是 3D 玩家动作、敌人、关卡、碰撞和镜头，并不是 Merge-2 手游配方。因此本项目只采用可迁移的上位原则：用简单操作产生连续感官反馈、让可交互目标主动吸引手指、让玩家路径和视线始终指向下一步，以及在风险、回报和喘息之间安排节奏；不生搬硬套战斗、跳跃或 3D 镜头方案。

## 3. 转化为七条可执行原则

1. **先写情绪目标，再写材料数量。** 每个节点只能有一个主情绪，例如“第一封信终于能送出”或“十年后圣殿再次听见笑声”；材料、对话、交互、音效共同服务它。
2. **教学发生在动作里。** 第一次给确定的发光目标和三步操作；玩家掌握后撤掉文字，只保留可重开的情境提示。
3. **行动必须改变世界。** 交付不是结束。玩家还要亲手架梁、点火、挂灯或选纹样，随后才进入角色回应和奖励。
4. **节奏不是难度单调上升。** 每章交替出现操作高潮、快速结算的喘息节点、个人选择和章末奇观，避免十二次相同流程。
5. **选择要留下证据。** 当前选择不伪装成分支结局，但会写入存档和回忆手账；文案不再告诉玩家“不会改变结局”。
6. **一次动作至少给三层反馈。** 目标亮起是预期，点击后的火花/音效/触感是即时确认，场景完成文案和角色回应是结果意义。
7. **新模式只加一层。** 前三章继续维持 Merge-2 核心，不同时引入复杂战斗或经营系统；每章只增加一种新的表达：第一章亲手复苏，第二章留下个人标记，第三章把选择提升为守焰人身份。

## 4. v0.3 前三章节拍已落地

改动前，前三章 12 个节点中只有 4 个节点存在场景交互，连续多个节点都是“备料—交付—看对白”。改动后共有 9 个交互节点；每章保留 1 个快速结算/剧情喘息节点，不把每次胜利都拖成长动画。

| 章节 | 节点节拍 | 玩家实际做的事 |
|---|---|---|
| 第一章 · 苏醒之村 | `n11 操作 → n12 喘息 → n13 操作 → n14 选择` | 守住第一点火；修屋快速兑现；亲手架桥让第一封信通过；选择村厅主灯 |
| 第二章 · 糖霜工坊街 | `n21 操作 → n22 选择 → n23 喘息 → n24 奇观` | 唤醒烤箱；设计第一条归乡围巾；快速破冰；沿整条街点亮灯宴 |
| 第三章 · 永暖圣殿 | `n31 操作 → n32 选择 → n33 奇观 → n34 喘息/揭示` | 挡风、安炉、点火；设计穹顶星图；完成三件供物仪式；安静读出四种人间温度 |

本轮新增的两个选择：

- `n22`：归雁纹 / 炉火纹 / 霜星纹；写入裁缝铺招牌和回忆手账。
- `n32`：归雁星阵 / 守望猎弓 / 风灯星环；写入穹顶和回忆手账。

这些选择当前属于“表达型选择”：不改变数值最优解，不制造玩家没预料到的惩罚，也不声称已经做出昂贵的分支剧情。后续美术升级时，应让所选纹样真实显示在对应场景 CG 上，形成第二层持久反馈。

## 5. 剧情与玩法为什么这样结合

- `n13` 不再只是桥修好了以后由波波口头汇报；玩家先架主梁、收桥索、挂路灯，波波才踩过玩家铺出的路。
- `n21` 用“敲霜—添柴—点火”把材料交付转成烤箱苏醒，完成态直接落到“有人循香开窗”的人物结果。
- `n22` 把普通裁缝订单变成玩家第一次给山谷留下图案，建立“这是我的山谷”的所有权感。
- `n31` 把抽象的“修缮大厅”拆成挡风、安炉和点火，所有点击都能解释为什么大厅重新适合人居住。
- `n32` 用穹顶星图承接第一章的风灯、冈特守望和第二章的归乡主题，让前三章的意象在同一选择界面汇流。

对白仍全部使用原有稳定 `voiceId`，所以 864 条中英日韩离线剧情语音继续逐句对应；新增内容是操作标题、提示、完成反馈和选择文案，不假装成未配音的对白。

## 6. 翻译生产流程

本轮新增 37 条玩家可见文本严格走两层流程：

```text
简体中文权威源
  → 本地 gemma4:12b 生成英 / 日 / 韩初稿与持久缓存
  → ChatGPT 逐条校正角色语气、按钮长度、术语和误译
  → tools/i18n/reviewed/{en,ja,ko}.json 锁定审校稿
  → 结构 / ID / 占位符 / 漏翻 / 术语门禁
```

这次二审实际纠正了几类本地模型问题：把 Gunnar 误写成 Gramps、把韩语“霜晶”误成“霜灵”、把日语围巾误成披肩，以及把已删除的“选择不改变结局”旧意保留在译文中。审校层与机器缓存分离，后续换本地模型不会覆盖已确认稿。

## 7. 自动验收与下一轮试玩指标

自动门禁新增以下约束：

- 前三章每章至少 2 个三步操作、1 个三选一表达型选择和 1 个喘息节点。
- 交互必须有标题、动机提示、结果反馈；步骤坐标合法，选项 ID 唯一并可安全持久化。
- 英/日/韩与中文保持相同节点、数值、交互结构、ID 和占位符。
- 窄屏 E2E 必须无横向溢出、弹窗越界或 JavaScript 错误。

“更有趣”最终仍需真人试玩验证，下一轮记录：

- 首次有效合并、首次完成场景操作、首次主动打开任务架的耗时。
- `n13 / n21 / n31` 三步操作的中断率和平均完成秒数。
- `n14 / n22 / n32` 三个选择的分布、取消率与回忆手账打开率。
- 每个节点对白跳过率、完成节点后 30 秒内再次合并的比例。
- 第一、二、三章完成率，以及玩家第一次因缺料停顿超过 60 秒的位置。

若玩家已经会合并却仍觉得重复，下一步优先做“有限目标变化”（指定连击、棋盘空间谜题、角色联合委托）和选择结果的真实场景换装；不继续单纯增加材料阶数或用更长对白掩盖重复。
