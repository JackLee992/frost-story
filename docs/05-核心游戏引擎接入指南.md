# Frost Merge Core 接入与维护指南

## 仓库分工

| 仓库 | 包含 | 不包含 |
|---|---|---|
| `frost-merge-core` | 交易结果契约、重复交互保护、稳定视图刷新、渲染元数据隔离 | 剧情、数值、美术、Pixi/Unity/Godot 特定 API |
| `frost-story` | 棋盘规则、订单/商店/剧情、Pixi 场景、Android 壳、下载站 | 可跨项目独立演进的基础契约 |

当前游戏把核心仓库固定在 `web/js/engine` submodule。浏览器无需 bundler，Android assets 同步脚本也能将它原样打包。

## 克隆当前游戏

```bash
git clone --recurse-submodules https://github.com/JackLee992/frost-story.git
```

已克隆但缺少引擎目录：

```bash
git submodule update --init --recursive
```

## 新的免打包 Web/Android 项目

```bash
git submodule add https://github.com/JackLee992/frost-merge-core.git web/js/engine
```

```js
import { actionFail, actionOk } from '../engine/src/action-result.js';
import { runActionOnce } from '../engine/src/stable-view.js';
```

Android 打包前要复制完整 `web/`，CI checkout 必须开启 `submodules: recursive`。

## Vite/Webpack/Rollup 项目

```bash
npm install github:JackLee992/frost-merge-core#v0.1.0
```

```js
import { actionOk, createDisplayMetaStore } from '@frost-story/merge-core';
```

产品发布必须使用 tag 或完整 commit SHA，不得依赖 `main` 浮动分支。

## 引擎升级流程

1. 在 `frost-merge-core` 先建立能失败的最小回归。
2. 修复并跑 `npm test`，打 SemVer tag。
3. 宿主项目更新 submodule 到该 tag 对应的 commit。
4. 宿主重跑逻辑、浏览器、Android 构建和真机回归。
5. 宿主只提交 submodule 新指针，发布说明记录核心版本。

```bash
cd web/js/engine
git fetch --tags
git checkout v0.1.0
cd ../../..
npm test
git add web/js/engine
```

## 通用修复的判定标准

同时满足以下条件才进核心仓库：

- 与剧情、商店价格、具体素材无关。
- 至少可被两种游戏或两种技术宿主调用。
- API 可独立单测，不需 PixiJS 或 Android 环境。
- 不把宿主业务状态倒置为核心包的依赖。

不符合的修复留在宿主适配层，但仍要在问题台账和回归中留证。
