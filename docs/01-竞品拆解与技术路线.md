## 二、竞品核心玩法系统（从类名与埋点字段还原）

1. **合并棋盘 Board**：`MergeGameBoard`、`BoardCells/BoardSize/BoardColumn/BoardRow`（存在 board33/board44 预设）、`BoardSpaceUnlockCount`（金币/等级解锁格子）、`BoardMaxBubbleCount`、`BoardPressureThreshold`（棋盘过满提示）、Warehouse 仓库（可扩展槽位）。
2. **棋子 Chess（= 棋盘物品）**：`MergeChessType`、`ChessGroup`（物品族）、`ChessChain/Level`（合成链与层级）、`chessbg1/2/3`（稀有度底色）、`OnMergeReduceAndAutoLevelUp`（**两个相同物品拖拽合并升一级 = Merge-2**）。
   - 物品族实测：`Main`（主线链）、`Clothing`、`Flower`、`Food`、`Fruit`、`Joy`、`Toy`、`Coin`、`Gem`。
3. **生成器 Generator（产出源）**：`GeneratorProduceLogic`、`generatorChains`、普通/幸运产出权重（normal/lucky output weight）、产出上限（output cap）、`generatorEnterCdCount`（点若干次进入冷却/充能）、`generator_max_levels`、有限使用次数（usesleft）。各族生成器如 `ClothingGenerator01..11`、`ToyGenerator`、`JoyGenerator`。
4. **体力 Energy**：`energy_multiplier`、`session_energy_use`、`reward_eq_energy`、体力购买弹窗、体力战斗通行证；点生成器消耗体力，体力随时间恢复。
5. **订单 Order/Tray**：顶部订单槽 `orderTray/TrayID/OrderNum/ScoreNum/FinishNum`、`TrayMaxCount`、`OrderSameChainDiffLevel`（同链不同级都可提交）、`submit_order`、订单角色 `orderroleres dc1..6`、订单宝箱。提交合并产物换金币/经验/分数。
6. **货币**：Coin（金币，含金币棋子/金币箱）、Gem/钻石（`Gem_10..500`）、physical（体力）、deco_token（装修代币）。
7. **等级/关卡 Stage**：玩家等级 `level_up/level_gate`（等级门槛解锁）、`stage_score/stage_upgrade/stage_rewards`、`LevelChess`（特殊关卡棋子，可分裂 split）。
8. **宝箱/抽卡 Gacha**：`MergeChestGacha`（定时宝箱，可钻石跳过倒计时）、企鹅抽卡、三连抉择宝箱 `TripleChoiceTreasure`、幸运盒。
9. **霜泡 Bubble**：`bubblechess/assetbubblechess`，产出物被泡泡锁住，`lt_buy_bubble/lt_get_bubble`（等待免费 / 看广告或钻石开）。
10. **剧情+装修 Story**：章节 `chapter_1001…`、对话 dialogue、`story_build/renovate_wall`（花资源重建）、`StoryBridgeMerge`（剧情桥接小游戏）、换装 makeover（old/new skin）。
11. **图鉴 Handbook / 卡片收藏**：按红/蓝/绿/黄/紫/棕分族的收集卡。
12. **外围系统**：每日/每周任务、BattlePass/PrizePath、签到、新手引导（NewUserGuide 强引导）、微笑值 Smile（顾客满意度进度）、以及大量限时活动（snowstormrush、flamingfrenzy、tournament、coinrace、penguinski…）。

**核心循环**：点生成器(耗体力)→产出链物品→两两合并升级→提交顶部订单→得金币/经验→买生成器/宝箱、扩棋盘、升级→推进剧情重建山谷→解锁新链与新章节。

## 三、《冰霜物语》技术选型（对齐 + 可落地）

用户已明确：**先 Android（iOS 后续）、独立 WebView 内核保稳定、WebGL 做游戏核心引擎**。据此选型：

```
┌────────────────────────────────────────────────────────┐
│  Android App（Kotlin, 单 module, minSdk26/targetSdk36） │
│  ├─ GeckoView（Mozilla 独立 Gecko 内核，不依赖系统WebView）│
│  ├─ 本地 AssetHttpServer(127.0.0.1, 纯 JDK ServerSocket) │
│  │    └─ 把 assets/web 以 http 提供 → fetch/WebGL/音频无跨域问题│
│  └─ 沉浸式全屏 / 返回键 / 生命周期托管                     │
├────────────────────────────────────────────────────────┤
│  游戏前端（assets/web，一套代码三端复用）                  │
│  ├─ 渲染：PixiJS v8 WebGL2(自动回退WebGL1) 棋盘/精灵/动画/粒子│
│  ├─ UI：HTML/CSS 叠加层（HUD/订单/弹窗，文字清晰、易本地化） │
│  ├─ 逻辑：原生 ES Module，数据驱动 config/*.json          │
│  ├─ 存档：localStorage（对标 Realm 本地库；预留云存档接口）  │
│  ├─ 音频：WebAudio（BGM+音效，AI 生成 wav）               │
│  └─ 分包：core/story/activity 目录，对标 YooAsset 三包，便于后续热更│
└────────────────────────────────────────────────────────┘
```

**为什么用「独立内核 + 本地 HTTP」而不是系统 WebView 直接 file://**
- 国产机型系统 WebView 版本碎片化（WebGL/音频/fetch 行为不一致）是主要崩溃源；GeckoView 自带同一版 Gecko 引擎，所有机型一致 = 稳定。
- `file://` 下 `fetch` 本地 JSON、音频自动播放常被拦；App 内起 `127.0.0.1` 静态服务后，行为与线上一致，也为后续「差量热更」预留同一套 URL 通道。
- 游戏逻辑与渲染全部在 Web 层，iOS 后续只需换 WKWebView 壳（或同样内嵌独立内核），**游戏代码零改动**。

**与竞品的工程对标关系**：Unity(IL2CPP) → WebGL(PixiJS)；YooAsset 三包 → web/packages 三包 + 版本清单；Realm → localStorage(+云存档接口)；Spine 骨骼 → Pixi 补间/粒子（后续可接 spine-pixi）；DDA 服务端调优 → 预留 `config/balance.json` 远程下发位。
