# 冰霜物语 v0.1 故障复盘与回归清单

> 本文记录首个可玩版中已遇到的用户可见问题、真正根因、修复方式和防再发测试。新游戏应直接复用末尾的发布门禁。

## 处理原则

- 现象和根因分开记录；“看起来像网格”不等于根因就在网格层。
- 状态改动先校验后写入，失败分支必须零写入。
- UI 只在命令成功时关闭或局部刷新；失败只显示原因。
- 渲染引擎对象不存放业务自定义字段，跨帧信息放进 `WeakMap`。
- 每个修复至少有一个可自动重现的用例，并在 Android 真机重跑核心路径。

## 问题台账

| ID | 现象 | 根因 | 通用修复 | 回归 |
|---|---|---|---|---|
| FS-001 | Android 启动期存在 Gecko 子进程重复初始化风险 | `Application.onCreate()` 会进入 GPU/内容/崩溃辅助进程 | `GeckoRuntime` 用主进程 Activity 首次访问的同步惰性单例 | Android 启动、前后台、重启 |
| FS-002 | 重启后像“存档丢失” | 本地 HTTP 随机端口改变 origin，`localStorage` 按 origin 隔离 | 回环服务器固定优先使用 `127.0.0.1:17843` | E2E 重载存档；真机强停/重启 |
| FS-003 | 全屏后 HUD、棋盘或底部按钮被挖孔/手势区遮挡 | 沉浸式全屏没有约束核心内容 | 原生层读取 `DisplayCutout` 与强制手势边距，换算 CSS px，全界面共用安全矩形 | 四方向 E2E 边界断言；真机截图 |
| FS-004 | “爽玩”按钮遮挡内容，Android 拖动后偶发不保存 | 位置固定；某些触摸序列以 `pointercancel` 结束 | 可拖动、安全区限幅、左右吸边；移动中防抖保存，`up/cancel` 共用收尾 | E2E 吸边、不压导航、重载持久化 |
| FS-005 | 屏幕出现多条贯穿全屏的蓝色竖条 | 动画把起点写入 Pixi 内部字段 `_sx/_sy`，破坏 Transform 矩阵缓存，节点高度膨胀到上万像素 | 动画起点放闭包；所有棋子元数据迁移到核心包的 `WeakMap` store | E2E 断言节点 bounds 在 1–120 px，无业务 `_...` 字段 |
| FS-006 | 合并后旧节点残留，长时游玩会叠加隐形对象 | `tween` 销毁回调误传第四参数 | 销毁函数传入 `onDone`，完成时删除 `WeakMap` 元数据 | E2E 断言场景子节点数等于状态节点数 |
| FS-007 | 合并成功但图像偶发仍是上一阶 | 纹理缓存 key 只含家族，未含阶级 | key 同时含 `family + tier` | 六步教学真实拖拽 E2E |
| FS-008 | 点商店条目时列表反复收起/显示，然后提示金币不足 | 无论交易成败都再调 `_shop()`，而 `modal()` 先销毁旧弹窗 | 状态命令返回 `ActionResult`；失败不重绘，成功只替换 `.m-body`并恢复滚动位置 | 6 类失败零写入；E2E 检查弹窗 identity/scrollTop |
| FS-009 | 融冰、宝箱钻石加速失败时仍关闭确认框 | UI 无条件 `closeModal()` | 确认类交互统一通过 `runActionOnce`，仅成功回调关闭 | E2E 覆盖钻石/金币不足时确认框仍在 |
| FS-010 | 霜泡外观在多次刷新后积累隐藏 Text 子节点 | `Graphics.clear()` 只清几何，不删子节点 | 更新前 `removeChildren()` 并销毁旧覆盖层 | E2E 连续 20 次 sync 后仍只有 1 个子节点 |
| FS-011 | 新手首单可随机成当前无法完成的需求 | 教学依赖随机订单 | 首单固定为首次合并得到的二阶结晶，奖励足够继续融冰 | 逻辑测试 + 六步教学 E2E |
| FS-012 | 动态更新 ZIP 可带来路径穿越、超大包或半更新 | 将网络包当作可信输入 | HTTPS 白名单、SHA-256、大小/数量/解压配额、路径校验，验证后原子切换且下次启动生效 | Android 测试/lint，内容包 SHA，真机启动 |
| FS-013 | 引入 Git submodule 后，开发元数据可被带入 APK/内容包 | 直接复制整个 submodule，其中 `.git`、CI、测试与文档均非运行时必需 | 发布只保留 `engine/src`；本地服务与 ZIP 另外拒绝任何隐藏路径段 | Kotlin 路径策略单测；检查 APK/ZIP 文件清单 |

## 竖条问题的定位过程

1. 先将 48 个网格连续描边改为弱填充/落点，视觉噪声降低，但全屏竖条仍在。
2. 依次隔离 grid、item、fx、snow 和生成器，确认竖条只属于 `itemLayer`。
3. 检查活动 DisplayObject bounds，发现新节点高度从 0 跳到约 16566 px。
4. 对照 Pixi Transform 后确认业务代码写入同名 `_sx/_sy`。
5. 用闭包保存动画起点立即消除竖条；再将所有自定义节点字段迁入 `WeakMap`，防止未来引擎版本出现新冲突。

该过程说明：图形异常应使用“分层隔离 + bounds 数值检查”，不能只靠截图猜 CSS 或网格样式。

## 交易交互契约

```text
点击按钮
  → runActionOnce 拦截重复激活
  → GameState 完成全部前置校验
      → 失败 ActionResult: 零写入 + 弹窗不动 + toast
      → 成功 ActionResult: 一次状态提交 + 局部刷新/关闭
```

已迁移的命令：商店宝箱、生成器、体力瓶、宝箱加速/开启、融冰、订单刷新和订单交付。

## 当前发布门禁

- 核心包：4 项 Node 单测。
- 游戏逻辑：72 项，包含失败交易原子性和三章九节点通关。
- 游戏浏览器：4 条 E2E，覆盖安全区、爽玩按钮、六步教学、渲染 bounds 和失败交互。
- 下载站：桌面/移动两条 E2E。
- Android：单测、lint、debug/release 构建、APK 签名校验，再做目标真机安装和玩法冒烟。

## 修复位置

- 通用核心：`web/js/engine` Git submodule（`frost-merge-core`）。
- 业务状态：`web/js/core/GameState.js`。
- 商店/弹窗：`web/js/ui/UI.js`。
- Pixi 棋盘：`web/js/scenes/BoardScene.js`。
- 逻辑回归：`test/logic.test.js`。
- 浏览器回归：`test/e2e.spec.js`。
